# 기술 스펙 초안 — 봉인 카드 런처

> `docs/event-plan.md`의 이벤트를 윈도우 PC에서 구동하기 위한 구현 초안입니다.
> 아직 코드는 없습니다. 착수 시점에 이 문서를 기준으로 시작합니다.

---

## 1. 왜 Electron인가

웹페이지로 만들고 브라우저 전체화면으로 띄우는 방법도 됩니다. 훨씬 간단하고요.
그럼에도 Electron을 권하는 이유는 이 이벤트가 요구하는 게 "페이지"가 아니라 **"며칠간 켜져 있는 장치"**이기 때문입니다.

| 요구사항 | 브라우저 | Electron |
|---|---|---|
| 부팅 시 자동 실행 | ✗ | ✓ |
| 주소창·탭 없는 완전 전체화면 | 애매함 (F11, ESC로 빠져나감) | ✓ 커널 수준 kiosk |
| 인터넷 없이 동작 | 로컬 서버 필요 | ✓ |
| 결과 파일 암호화 저장 | localStorage — 개발자도구로 다 보임 | ✓ 앱 데이터 디렉터리 |
| 카운트다운 중 절전 방지 | ✗ | ✓ `powerSaveBlocker` |
| 개봉 시각 OS 알림 | 권한 팝업 필요 | ✓ |

특히 **"개발자도구 F12로 결과를 미리 볼 수 있다"**는 점이 브라우저 방식의 결정적 약점입니다.

### 대안 비교

- **Tauri** — 번들이 훨씬 가볍고(수 MB) 요구사항을 다 충족합니다. Rust 툴체인 설치가 필요한 게 유일한 부담.
  빌드 환경만 갖춰지면 Tauri가 더 나은 선택입니다.
- **Electron** — 번들이 크지만(~150MB) 자료가 압도적으로 많고 삽질이 적습니다. **기본안으로 채택.**

## 2. 스택

```
Electron + Vite + React + TypeScript
├─ 애니메이션   Framer Motion (카드 뒤집기, 봉인 파괴)
├─ 스타일       Tailwind CSS
├─ 폰트         Pretendard (오프라인 번들 — CDN 금지)
├─ 사운드       Howler.js (앰비언트, 개봉 SFX)
└─ 패키징       electron-builder → portable .exe
```

`portable .exe`로 빌드하면 설치 없이 USB에 담아 아무 윈도우 PC에서 실행할 수 있습니다.
당일 노트북이 바뀌는 상황에 대비해 이 형태를 권합니다.

## 3. 화면 구조

```
Boot          타이틀. "YOUNGEUN · 0919"
 │
 ├─ Draw      뽑기 (D-14, 1회성)
 │              뒷면 카드 배열 → 선택 → 봉인 애니메이션 → 잠김
 │
 ├─ Sealed    봉인 대기 (D-13 ~ D-day 09:19)
 │              봉인된 카드 2장 + 카운트다운 + 오늘의 힌트
 │
 ├─ Reveal    개봉 (D-day)
 │              봉인 파괴 → 선물 → 목적지 → 초대장
 │
 └─ Journey   여정 (개봉 이후 상시)
                1박 2일 타임라인, 언제든 재열람
```

앱 실행 시 저장된 상태를 읽어 위 다섯 중 하나로 직행합니다. 화면 간 수동 이동은 없습니다.

### 주최자 모드 (다영 전용)

`Ctrl+Shift+D` → PIN 입력. 이 안에서만:

- 실제 뽑기 결과 확인 (예약을 위해 필수)
- 개봉 시각 변경
- 임의 화면으로 점프 (리허설용)
- 상태 초기화

이 모드가 없으면 결과를 알 방법이 없어 예약을 할 수 없습니다. **1순위 구현 대상입니다.**

## 4. 상태 저장

```
%APPDATA%/youngeun-0919/
├─ state.json      단계, 뽑기 시각, 마지막 실행 시각, 공개된 힌트 인덱스
└─ sealed.bin      암호화된 뽑기 결과
```

### `state.json`

```jsonc
{
  "phase": "sealed",              // boot | draw | sealed | reveal | journey
  "drawnAt": "2026-09-05T20:00:00+09:00",
  "revealAt": "2026-09-19T09:19:00+09:00",
  "hintsShown": 7,
  "lastSeenAt": "2026-09-12T21:33:10+09:00",  // 시계 되감기 감지용
  "revealed": false
}
```

### 봉인 (`sealed.bin`)

결과 JSON을 AES-256-GCM으로 암호화합니다. 키는 다영이 앱 설정 시 입력한 패스프레이즈에서
PBKDF2로 유도하고, **어디에도 저장하지 않습니다.**

개봉 시점의 복호화는 두 가지 방식이 가능합니다.

- **(a) 다영이가 당일 아침 패스프레이즈 입력** — 가장 확실합니다. 다만 다영이가 그 자리에 있어야 합니다.
- **(b) 앱에 키 조각을 내장하고 시각 도달 시 자동 결합** — 자동으로 열리지만, 파일을 뜯으면 이론상 복호화 가능합니다.

현실적으로 이건 연인 간 이벤트이므로 **(b)로 충분**합니다. 목적은 암호학적 안전성이 아니라
"실수로 미리 보는 것"과 "궁금해서 파일 열어보는 것"을 막는 정도입니다. 다만 `sealed.bin`이
평문 JSON이면 파일 탐색기에서 우연히 열어봐도 다 보이므로, 암호화 자체는 반드시 넣습니다.

### 시계 조작 방지

`lastSeenAt`을 매 실행마다 기록하고, 현재 시각이 그보다 **과거면** 시계를 되돌린 것으로 판단해
경고를 띄웁니다. 완벽한 방어는 아니지만(전진 조작은 못 막음) 실질적인 억제 효과는 충분합니다.
전진 조작까지 막으려면 개봉 시각 확인에 NTP나 외부 API를 써야 하는데, 오프라인 요구사항과
충돌하므로 권하지 않습니다.

## 5. 카운트다운 정확도

노트북이 절전에 들어가면 `setInterval` 기반 카운트다운은 어긋납니다. 두 가지를 함께 씁니다.

- 표시는 `setInterval`이 아니라 **매 tick마다 `Date.now()`와 목표 시각의 차이를 재계산**합니다.
- 개봉 직전(D-day 전날 밤부터)에는 `powerSaveBlocker.start('prevent-display-sleep')`로 절전을 막습니다.
  전날 밤 화면을 켜둔 채 자는 연출 자체가 이 API에 의존합니다.

## 6. 콘텐츠 자산

코드보다 이쪽 준비가 오래 걸립니다. 개발과 병행해야 합니다.

| 자산 | 수량 | 비고 |
|---|---|---|
| 카드 뒷면 디자인 | 1 | 조커 도입 시 미묘하게 다른 버전 1개 추가 |
| 선물 이미지 | 2~3 | 제품 공식 이미지 |
| 목적지 사진 | 2 | 각 3~4장 (개봉 연출용 풀스크린) |
| 힌트 이미지·문구 | 13 | 목적지 사진의 확대 크롭 + 단어 |
| 지도 이미지 | 2 | 오프라인 표시용 캡처 (지도 API 연동 불필요) |
| 사운드 | 3 | 앰비언트 루프, 봉인 파괴, 카드 뒤집기 |

전부 앱에 번들합니다. 당일 인터넷이 안 되는 상황에서도 완주해야 합니다.

## 7. 개발 순서

1. Electron + Vite 셸, kiosk 전체화면, 상태 파일 읽기/쓰기
2. **주최자 모드 + 뽑기 화면** — D-14 세리머니에 필요한 최소 기능. 여기까지가 1차 마감
3. 봉인 대기 화면 + 카운트다운 + 힌트
4. 개봉 연출 (가장 공들일 부분)
5. 여정 화면
6. 리허설 — 시각을 조작해 전체 플로우를 처음부터 끝까지 3회 이상 통과

**6번을 건너뛰지 마세요.** 이 앱은 실행 기회가 단 한 번이고 재시도가 없습니다.
실제 개봉 시각을 몇 분 뒤로 당겨두고 전체 흐름을 통째로 돌려보는 리허설이 반드시 필요합니다.
