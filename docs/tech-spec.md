# 기술 스펙 초안 — 봉인 카드 런처

> `docs/event-plan.md`의 이벤트를 윈도우 PC에서 구동하기 위한 구현 초안입니다.
> 아직 코드는 없습니다. 착수 시점에 이 문서를 기준으로 시작합니다.

---

## 1. 왜 Electron인가

웹페이지로 만들고 브라우저 전체화면으로 띄우는 방법도 됩니다. 훨씬 간단하고요.
그럼에도 Electron을 권하는 이유는 이 이벤트가 요구하는 게 "페이지"가 아니라 **"며칠간 켜져 있는 장치"**이기 때문입니다.

| 요구사항 | 브라우저 | Electron |
|---|---|---|
| 부팅 시 자동 실행 | ✗ | ✓ |
| 주소창·탭 없는 완전 전체화면 | 애매함 (F11, ESC로 빠져나감) | ✓ 커널 수준 kiosk |
| 인터넷 없이 동작 | 로컬 서버 필요 | ✓ |
| 결과 파일 암호화 저장 | localStorage — 개발자도구로 다 보임 | ✓ 앱 데이터 디렉터리 |
| 카운트다운 중 절전 방지 | ✗ | ✓ `powerSaveBlocker` |
| 개봉 시각 OS 알림 | 권한 팝업 필요 | ✓ |

특히 **"개발자도구 F12로 결과를 미리 볼 수 있다"**는 점이 브라우저 방식의 결정적 약점입니다.

### 대안 비교

- **Tauri** — 번들이 훨씬 가볍고(수 MB) 요구사항을 다 충족합니다. Rust 툴체인 설치가 필요한 게 유일한 부담.
  빌드 환경만 갖춰지면 Tauri가 더 나은 선택입니다.
- **Electron** — 번들이 크지만(~150MB) 자료가 압도적으로 많고 삽질이 적습니다. **기본안으로 채택.**

## 2. 스택

```
Electron + Vite + React + TypeScript
├─ 애니메이션   Framer Motion (카드 뒤집기, 봉인 파괴)
├─ 스타일       Tailwind CSS
├─ 폰트         Pretendard (오프라인 번들 — CDN 금지)
├─ 사운드       Howler.js (앰비언트, 개봉 SFX)
└─ 패키징       electron-builder → portable .exe
```

`portable .exe`로 빌드하면 설치 없이 USB에 담아 아무 윈도우 PC에서 실행할 수 있습니다.
당일 노트북이 바뀌는 상황에 대비해 이 형태를 권합니다.

## 3. 화면 구조

```
Boot          타이틀. "YOUNGEUN · 0919"
 │
 ├─ Draw      뽑기 (D-14, 1회성)
 │              뒷면 카드 배열 → 선택 → 봉인 애니메이션 → 잠김
 │
 ├─ Sealed    봉인 대기 (D-13 ~ D-day 09:19)
 │              봉인된 카드 2장 + 카운트다운 + 오늘의 힌트
 │
 ├─ Reveal    개봉 (D-day)
 │              봉인 파괴 → 선물 → 목적지 → 초대장
 │
 └─ Journey   여정 (개봉 이후 상시)
                1박 2일 타임라인, 언제든 재열람
```

앱 실행 시 저장된 상태를 읽어 위 다섯 중 하나로 직행합니다. 화면 간 수동 이동은 없습니다.

### 주최자 모드 (다영 전용)

`Ctrl+Shift+D` → PIN 입력. 이 안에서만:

- 실제 뽑기 결과 확인 (예약을 위해 필수)
- 개봉 시각 변경
- 임의 화면으로 점프 (리허설용)
- 상태 초기화

이 모드가 없으면 결과를 알 방법이 없어 예약을 할 수 없습니다. **1순위 구현 대상입니다.**

## 4. 상태 저장

```
%APPDATA%/youngeun-0919/
├─ state.json      단계, 뽑기 시각, 타일 해제 상태, 데일리 키 이력
├─ sealed.bin      암호화된 뽑기 결과
├─ commit.json     해시 커밋 (평문 — 검증용이라 숨길 필요 없음)
└─ photos/         여정 모드에서 올린 사진
```

### `state.json`

```jsonc
{
  "phase": "sealed",              // boot | draw | sealed | reveal | journey | capsule
  "drawnAt": "2026-09-05T20:14:00+09:00",
  "revealAt": "2026-09-19T09:19:00+09:00",
  "lastSeenAt": "2026-09-12T21:33:10+09:00",  // 시계 되감기 감지용

  "days": {                       // 처리 완료된 날짜만 키로 존재
    "2026-09-06": { "key": "scratch", "done": true,  "bonus": 0 },
    "2026-09-07": { "key": "quiz",    "done": true,  "bonus": 1 },
    "2026-09-08": { "key": "letter",  "done": true,  "bonus": 0 }
  },

  "tiles": {                      // 카드별 해제된 타일 인덱스
    "gift":        [0, 5, 8, 9, 17, 23],
    "destination": [2, 3, 11, 14, 20, 27]
  },

  "revealed": false,
  "missionChecks": [false, false, false]
}
```

`days`를 날짜 키로 두는 이유는 **밀린 날 처리** 때문입니다. 실행 시 `drawnAt`부터 오늘까지의
날짜를 순회하며 `days`에 없는 날을 찾아 순차 재생합니다. "며칠째인지"를 카운터로 들고 있으면
시계가 흔들릴 때 어긋납니다.

### 타일 해제 규칙

카드당 54타일(6 × 9). 하루 기본 2장 + 퀴즈 정답 보너스 1장, **공개 상한 40장**.
나머지 14장은 `locked` 배열로 콘텐츠 정의에 하드코딩하며 D-day 전에는 어떤 경로로도 열리지 않습니다.

```jsonc
// content/cards.json — 카드별 콘텐츠 정의
{
  "id": "destination-glamping",
  "image": "assets/dest-glamping.jpg",
  "locked": [21, 22, 23, 30, 31, 32, 39, 40, 41, 48, 49, 50, 12, 13],
  "order":  [0, 8, 45, 53, 1, 9, ...]   // 열리는 우선순위 (배경 → 외곽선)
}
```

`order`는 무작위로 생성하지 말고 이미지마다 손으로 정합니다. 배경부터 열려야
정보가 새지 않습니다. 자세한 근거는 `docs/mechanics.md` §1.2.

### 봉인 (`sealed.bin`)

결과 JSON을 AES-256-GCM으로 암호화합니다. 키는 다영이 앱 설정 시 입력한 패스프레이즈에서
PBKDF2로 유도하고, **어디에도 저장하지 않습니다.**

개봉 시점의 복호화는 두 가지 방식이 가능합니다.

- **(a) 다영이가 당일 아침 패스프레이즈 입력** — 가장 확실합니다. 다만 다영이가 그 자리에 있어야 합니다.
- **(b) 앱에 키 조각을 내장하고 시각 도달 시 자동 결합** — 자동으로 열리지만, 파일을 뜯으면 이론상 복호화 가능합니다.

현실적으로 이건 연인 간 이벤트이므로 **(b)로 충분**합니다. 목적은 암호학적 안전성이 아니라
"실수로 미리 보는 것"과 "궁금해서 파일 열어보는 것"을 막는 정도입니다. 다만 `sealed.bin`이
평문 JSON이면 파일 탐색기에서 우연히 열어봐도 다 보이므로, 암호화 자체는 반드시 넣습니다.

### 해시 커밋 (`commit.json`)

뽑기 시점에 결과를 해싱해 커밋해 둡니다. 개봉 후 "나중에 바꾼 것 아니냐"에 대한 답입니다.
자세한 취지는 `docs/mechanics.md` §4.

```jsonc
// commit.json — 평문. 검증용이므로 숨기지 않습니다
{
  "algo": "SHA-256",
  "digest": "a7f32c918e04b1d6…",   // 앞 12자리를 증서에 인쇄
  "committedAt": "2026-09-05T20:14:00+09:00"
}
```

```
digest = SHA-256( JSON.stringify(result) + salt )
```

`salt`는 뽑기 시 생성해 `sealed.bin` 안에 결과와 함께 넣습니다. 개봉 시 둘 다 공개되고,
앱의 검증 화면이 그 자리에서 다시 해싱해 `commit.json`의 값과 대조합니다.
**직렬화 순서가 흔들리면 검증이 깨집니다** — 키 순서를 고정한 canonical JSON으로 직렬화하세요.

### 시계 조작 방지

`lastSeenAt`을 매 실행마다 기록하고, 현재 시각이 그보다 **과거면** 시계를 되돌린 것으로 판단해
경고를 띄웁니다. 완벽한 방어는 아니지만(전진 조작은 못 막음) 실질적인 억제 효과는 충분합니다.
전진 조작까지 막으려면 개봉 시각 확인에 NTP나 외부 API를 써야 하는데, 오프라인 요구사항과
충돌하므로 권하지 않습니다.

## 5. 런타임 정확도

### 카운트다운

노트북이 절전에 들어가면 `setInterval` 기반 카운트다운은 어긋납니다. 두 가지를 함께 씁니다.

- 표시는 `setInterval`이 아니라 **매 tick마다 `Date.now()`와 목표 시각의 차이를 재계산**합니다.
- 개봉 직전(D-day 전날 밤부터)에는 `powerSaveBlocker.start('prevent-display-sleep')`로 절전을 막습니다.
  전날 밤 화면을 켜둔 채 자는 연출 자체가 이 API에 의존합니다.

### 날짜 경계

"오늘"의 기준은 자정이 아니라 **오전 5시**로 둡니다. 새벽 2시에 앱을 켠 건 전날의 연장이지
다음 날이 아닙니다. 자정 기준으로 두면 밤늦게 켰을 때 하루가 두 번 진행되는 것처럼 느껴집니다.

타임존은 `Asia/Seoul`로 고정합니다. 로컬 타임존을 따라가면 여행 중 시각이 흔들릴 여지가 있습니다.

## 6. 타일 · 블러 렌더링

카드 표면은 이미지 한 장 위에 세 겹이 겹칩니다. 전부 CSS로 처리 가능하며 캔버스가 필요 없습니다.

```
img            원본 이미지
 └ filter      blur(Npx) saturate(S%)   ← 레이어 ②③, 값은 D-day까지 남은 일수로 계산
 └ 타일 그리드  position:absolute 54개    ← 레이어 ①
```

- **타일**은 `opacity` + `transform: scale()` 전환으로 사라지게 합니다. 한 장씩 60ms 간격으로
  스태거를 주면 "벗겨진다"는 감각이 생깁니다. 동시에 사라지면 그냥 화면이 바뀐 것처럼 보입니다.
- **블러 값**은 상태에서 파생시킵니다. 저장하지 마세요.
  `blur = 60 - (60 - 6) × (경과일 / 13)`
- **채도**는 마지막 3일에만 `0% → 100%`. 그 전에는 `saturate(0)` 고정입니다.
- `filter: blur()`는 큰 이미지에서 GPU 부담이 있습니다. 원본을 1600px 이하로 리사이즈하고
  `will-change: filter`를 걸어두세요.
- `prefers-reduced-motion`에서는 스태거를 끄고 즉시 전환합니다.

### 스크래치 인터랙션

이것만 캔버스가 필요합니다. 은박 레이어를 캔버스에 채우고
`globalCompositeOperation = 'destination-out'`으로 마우스 궤적을 지웁니다.
지워진 픽셀 비율을 주기적으로 샘플링해 **60%를 넘으면 나머지를 자동으로 없앱니다.**
끝까지 다 긁게 하면 지루합니다.

긁는 소리를 반드시 넣으세요. 이 인터랙션은 소리가 절반입니다.

## 7. 알림과 트레이 상주

앱을 켜는 걸 잊으면 13일 설계가 통째로 무의미해집니다. 우선순위가 생각보다 높습니다.

- `Tray` API로 트레이에 상주. 창을 닫아도 종료되지 않고 트레이로 내려갑니다.
- 매일 21:00에 `Notification`으로 토스트. 클릭하면 창이 전체화면으로 올라옵니다.
- 알림 스케줄링은 `setTimeout` 대신 **1분 주기 폴링**으로 처리합니다. 절전에서 깨어났을 때
  긴 `setTimeout`은 발화 시각이 밀립니다.
- 자동 실행은 `app.setLoginItemSettings({ openAtLogin: true })`.

## 9. 여정 모드 (폰 웹)

집을 나서면 노트북은 두고 갑니다. 1박 2일 동안은 폰에서 열리는 별도 웹 페이지가 담당합니다.

- **정적 사이트.** Vercel이나 GitHub Pages로 충분합니다. 서버 로직 없음
- 일정 데이터는 빌드 시점에 박아 넣습니다. 뽑기 결과가 나온 뒤(D-13) 한 번 배포하면 끝
- 현재 시각 기준 다음 일정 하이라이트, 미션 체크박스, 시각이 지나야 열리는 한 줄 코멘트
- 사진 업로드는 `localStorage` + IndexedDB로 기기 로컬에만. 백엔드를 만들 이유가 없습니다
- **URL은 추측 불가능하게.** 랜덤 슬러그를 쓰세요. 인증은 과합니다

데스크톱 앱과 코드를 공유할 수 있으면 좋지만, 억지로 모노레포를 만들 필요는 없습니다.
화면 하나짜리라 그냥 따로 만드는 게 빠릅니다.

## 11. 개발 순서

`docs/mechanics.md` §9의 우선순위와 짝을 이룹니다.

1. Electron + Vite 셸, kiosk 전체화면, 상태 파일 읽기/쓰기
2. **주최자 모드 + 뽑기 화면 + 봉인** — 여기까지가 D-14 1차 마감
3. 봉인 대기 화면 — 카운트다운, 타일 + 블러, 밀랍 온도
4. 데일리 키 3종 + 밀린 날 순차 재생
5. 데스크톱 알림 + 트레이 상주
6. 개봉 연출 — 가장 공들일 부분
7. 검증 화면, Wrapped, QR 인계
8. 여정 웹 (별도 배포)
9. **리허설** — 시각을 조작해 전체 플로우를 처음부터 끝까지 3회 이상 통과
