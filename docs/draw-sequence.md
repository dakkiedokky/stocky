# 뽑기 시퀀스 — 야바위와 되돌릴 수 없는 선택

> ⛔ **보류 (2026-09-05 기준).** 선물과 숙소가 확정되면서 뽑을 대상이 사라졌습니다.
> 판단 근거와 대안은 [`pivot.md`](pivot.md)에 있습니다. **문서는 지우지 않습니다** —
> 나중에 뽑을 만한 대상이 다시 생기면 그대로 꺼내 쓸 수 있습니다.
>
> 슬롯당 3장. 한 번 고르고 끝나는 게 아니라 **흔들고, 되묻고, 멈칫하는** 시퀀스입니다.
> 세 개 중 하나로 운명이 갈리는 순간을 최대한 늘리는 게 목적입니다.

---

## 1. 슬롯 구성

| 슬롯 | 카드 | 상태 |
|---|---|---|
| **1 — 선물** | 3장 | 갤럭시 워치 9 / 갤럭시 탭 / 이북 |
| **2 — 호텔** | 3장 | 더미 A / 더미 B / 더미 C — [`hotels.md`](hotels.md)에서 확정 |

조합 3 × 3 = **9가지**. 조커는 없앴습니다. 3장이 딱 떨어져야 야바위가 성립하고,
"전부 다" 같은 보너스는 보장 게이지 보상([`mechanics.md`](mechanics.md) §1.3)으로 옮겼습니다.

슬롯 정의는 데이터입니다. 식당을 3장짜리 세 번째 슬롯으로 넣고 싶으면
`content/slots.json`에 항목만 추가하면 되고 코드는 건드릴 필요 없습니다.

## 2. 전체 시퀀스

```
P0  DEAL        3장이 뒷면으로 놓인다                      ⚑ 배치 확정 + 해시 커밋
P1  SHUFFLE     야바위. 스왑 7회, 2.6초
P2  PICK        "운명을 고르세요" → 1장 클릭
P3  ELIMINATE   나머지 2장 중 1장이 스스로 뒤집힌다        ⚑ 내용은 공개하지 않음
P4  OFFER       "남은 건 두 장. 바꾸시겠습니까?"           [그대로] [바꾼다]
P5  CONFIRM     "정말입니까? 되돌릴 수 없습니다."          [예] [아니요 → P4]
P6  FEINT       뒤집히려다 멈춘다. 화면이 흔들린다          ← 페이크 ①
P7  RESHUFFLE   50% 확률로 "한 번 더." 짧은 야바위          ← 페이크 ②
P8  SEAL        1.5초 홀드 → 밀랍
```

전체 약 40~55초. 슬롯 하나당입니다.

## 3. P1 야바위 — 애니메이션 상세

세 카드가 자리를 바꾸며 섞입니다. 컵 세 개 밑에 구슬 넣고 돌리는 그 동작입니다.

### 스왑 타이밍

가속했다가 **마지막에 느려지는 게 핵심**입니다. 끝까지 빠르면 그냥 포기하게 되고,
마지막이 느리면 *"어? 따라갈 수 있을 것 같은데"* 하는 착각이 생깁니다. 그 착각이 이 연출의 전부입니다.

| 스왑 | 길이 | 비고 |
|---|---|---|
| 1 | 350ms | 천천히 시작 — 규칙을 보여줌 |
| 2 | 180ms | |
| 3~5 | 150ms | 최고 속도. 여기서 시야를 놓침 |
| 6 | 220ms | 감속 시작 |
| 7 | 420ms | **느리게.** 눈이 다시 따라붙음 |

합 1.62초 + 시작·정지 여백 = 총 2.6초.

### 궤적

```
위치   A(-280px)      B(0)       C(+280px)      ← 1920 캔버스 기준
스왑   두 카드가 호를 그리며 교환.
       한 장은 앞쪽 호(z-index 위), 한 장은 뒤쪽 호(아래).
       겹치는 순서가 매번 같으면 기계처럼 보입니다 — 스왑마다 앞뒤를 뒤집으세요.
```

카드는 이동 중 살짝 기울어집니다(±6°). 정지할 때 0°로 돌아오며 아주 작게 튕깁니다.
사운드는 스왑마다 짧은 슬라이드 음, 마지막 정지에 착지음 하나.

## 4. P3 탈락 카드 — 정보를 흘리지 않기

플레이어가 고르지 않은 두 장 중 한 장이 스스로 뒤집힙니다.
**그런데 내용을 보여주면 안 됩니다.** 3장이 2장으로 좁혀지면 13일간의 긴장이 반토막 납니다.

그래서 탈락 카드는 **VOID 면**으로 뒤집힙니다.

```
┌─────────────┐
│             │
│      ✕      │      brass 얇은 테두리, 회색 X
│             │
│   탈락      │      Mono, ink-faint
│             │
└─────────────┘
```

의식은 그대로 일어나되 정보는 0입니다.
13일 내내 *"저건 뭐였을까"*가 남고, **개봉 때 공개됩니다** — "바꿨으면 이거였습니다."
이 공개가 도감(§6)의 빈칸을 채웁니다.

## 5. P4~P5 되묻기 — 몇 번까지 허용되나

```
P4   "남은 건 두 장. 바꾸시겠습니까?"        [그대로 간다]  [바꾼다]
P5   "정말입니까? 되돌릴 수 없습니다."        [예]  [아니요]
        └ [아니요] → P4로 복귀. 무한 반복 가능
```

P5에서 [아니요]를 누르면 P4로 돌아갑니다. **횟수 제한을 두지 마세요.**
고민하는 시간 자체가 이 시퀀스의 상품입니다. 다만 3회째부터는 문구를 바꿉니다.

| 회차 | P5 문구 |
|---|---|
| 1회 | 정말입니까? 되돌릴 수 없습니다. |
| 2회 | 진짜 정말입니까? |
| 3회+ | …정말이죠? |

3회째의 말줄임표가 웃음 포인트입니다. 재촉하지 않으면서 "너 지금 오래 고민하고 있어"를 알려줍니다.

## 6. P6~P7 페이크 — 예산은 2회

**이게 이 문서에서 제일 조심해야 할 부분입니다.** 페이크는 두 번까지입니다.
세 번을 넘기면 긴장이 아니라 짜증이 되고, 생일에 짜증은 회복이 안 됩니다.

### P6 FEINT — 필수

봉인 직전, 카드가 뒤집히려다 **20% 지점에서 멈춥니다.**
화면이 미세하게 흔들리고(±4px, 0.3초), 카드가 원위치로 돌아갑니다. 총 0.9초.
소리는 뚝 끊깁니다 — 갑작스러운 무음이 시각 효과보다 강합니다.

멈춘 뒤 화면 하단에 한 줄:

> *…아직입니다.*

### P7 RESHUFFLE — 50% 확률

절반의 확률로만 발생합니다. 매번 나오면 그건 페이크가 아니라 절차입니다.

> **한 번 더 섞겠습니다.**

짧은 야바위(스왑 3회, 1.4초)가 돌아갑니다. 그리고 카드는 그대로 봉인됩니다.

**결정적 구현 주의 — 재셔플 후에 다시 고르게 하지 마세요.**
카드는 시각적으로 계속 추적되고, 플레이어의 선택은 이미 P4에서 확정됐습니다.
여기서 다시 고르라고 하면 P2~P5의 모든 고민이 무의미해지고, 그 순간 이 시퀀스는
장난에서 조롱으로 넘어갑니다. **재셔플은 순수한 연출이고, 결과에 영향이 없습니다.**

---

## 7. 두 번째 슬롯은 짧게

선물 슬롯이 끝나면 호텔 슬롯이 이어집니다. **같은 연출을 두 번 온전히 하면 지루합니다.**

| 단계 | 슬롯 1 (선물) | 슬롯 2 (호텔) |
|---|---|---|
| P1 셔플 | 7회 / 2.6초 | **5회 / 1.8초** |
| P3 탈락 | ○ | ○ |
| P4 되묻기 | ○ | ○ |
| P6 페인트 | ○ | **✗ 생략** |
| P7 재셔플 | 50% | **✗ 생략** |

두 번째는 페이크를 전부 뺍니다. 이미 문법을 알고 있으니 같은 수를 또 쓰면 안 먹힙니다.
대신 **봉인 홀드를 2.0초로 늘려** 마지막 무게를 줍니다.

## 8. 결과 확정과 정직성

### 언제 무엇이 정해지나

```
P0   layout = shuffle([card0, card1, card2])     ← 실제 난수. 이때 확정
     salt   = randomBytes(16)
     commit = SHA-256( canonical(layout) + salt )   → 증서에 앞 12자리 인쇄

P2   pickedPos      ← 플레이어
P3   eliminatedPos  ← 안 고른 둘 중 무작위
P4   finalPos       ← 그대로면 pickedPos, 바꾸면 남은 하나

P8   result = layout[finalPos]
     sealed.bin ← { layout, salt, pickedPos, eliminatedPos, switched, finalPos }
```

**스위치가 결과를 실제로 바꿉니다.** 연출이 아니라 진짜입니다.
P7 재셔플은 `layout`을 건드리지 않습니다 — 화면상의 위치만 움직입니다.

개봉 시 `layout`과 `salt`가 공개되고, 앱이 그 자리에서 다시 해싱해 증서의 값과 대조합니다.
13일간 냉장고에 붙어 있던 종이와 숫자가 같으면 그날 정해진 게 맞습니다.

### 몬티홀이 아닙니다 — 그리고 그게 펀치라인

이 구조는 몬티홀 문제를 닮았지만 **수학적으로는 몬티홀이 아닙니다.**
진짜 몬티홀은 사회자가 정답을 알고 일부러 꽝을 여는 구조인데, 우리는

- 탈락 카드를 **무작위로** 고르고
- 애초에 **꽝이 없습니다**

그래서 바꾸든 안 바꾸든 확률은 의미가 없습니다. 셋 다 당첨이니까요.

이걸 개봉 화면에서 밝히세요.

> 바꾸는 게 유리했을까요?
> 아닙니다. 애초에 꽝이 없었거든요.
> 그래도 그때 한참 고민했잖아요.

**이 이벤트에서 제일 좋은 마무리 문구가 여기 있다고 생각합니다.**
40초를 고민하게 만들어놓고 마지막에 "다 당첨이었어"라고 밝히는 게,
이 기획 전체가 하려는 말이기도 하고요.

## 9. 상태 머신 (구현용)

```ts
type Phase =
  | 'deal' | 'shuffle' | 'pick' | 'eliminate'
  | 'offer' | 'confirm' | 'feint' | 'reshuffle' | 'seal' | 'done';

interface SlotDraw {
  slot: 'gift' | 'hotel';
  layout: string[];              // 카드 id 3개. P0에서 확정, 이후 불변
  salt: string;
  commit: string;                // sha256(canonical(layout) + salt)
  pickedPos:      number | null;
  eliminatedPos:  number | null;
  confirmCount:   number;        // P5에서 [아니요] 누른 횟수 — 문구 분기용
  switched:       boolean;
  finalPos:       number | null;
  feintsUsed:     number;        // 최대 2
}
```

### 전이 규칙

| 현재 | 입력 | 다음 |
|---|---|---|
| `deal` | 자동 (0.8s) | `shuffle` |
| `shuffle` | 자동 (2.6s) | `pick` |
| `pick` | 카드 클릭 | `eliminate` |
| `eliminate` | 자동 (1.4s) | `offer` |
| `offer` | 그대로 / 바꾼다 | `confirm` |
| `confirm` | 예 | `feint` (슬롯 1) · `seal` (슬롯 2) |
| `confirm` | 아니요 | `offer` — `confirmCount++` |
| `feint` | 자동 (0.9s) | 50% `reshuffle` · 50% `seal` |
| `reshuffle` | 자동 (1.4s) | `seal` |
| `seal` | 1.5s 홀드 완료 | `done` |
| `seal` | 홀드 중 손 뗌 | `seal` — 진행도 0으로 |

**되돌아가는 전이는 `confirm → offer` 하나뿐입니다.** 나머지는 전부 단방향입니다.
"되돌릴 수 없습니다"가 진짜여야 그 문구에 무게가 실립니다.

## 10. 주최자 오버라이드

예약이 불가능해지는 등 실무적 이유로 결과를 바꿔야 할 때가 있습니다.
`Ctrl+Shift+D` → PIN → 결과 지정.

**단, 오버라이드하면 `commit`을 다시 계산해야 하고 증서를 다시 인쇄해야 합니다.**
이미 인쇄한 증서가 있는데 결과만 바꾸면 개봉 때 검증이 실패합니다.
앱이 이 상황을 감지해 경고를 띄우게 하세요.

> 증서가 이미 발행되었습니다. 결과를 변경하면 검증이 실패합니다.
> 증서를 다시 인쇄하시겠습니까?

이 경고가 없으면 개봉 최고조에서 "검증 실패"가 뜹니다. **가장 뼈아픈 버그가 될 지점입니다.**
