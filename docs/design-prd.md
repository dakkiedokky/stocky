## 2. 디자인 방향

### 컨셉 한 줄

**밀랍으로 봉인된 편지가 13일 뒤에 열린다.**

### 무드

심야의 서재. 촛농이 굳은 봉투. 별이 뜬 창밖.
차갑고 조용한 화면에서 시작해 **개봉의 순간에만 뜨거워집니다.**

의도적으로 피할 것 — 파스텔 생일 파티, 풍선, 컨페티, 크림 톤, 손글씨 폰트.
이건 축하 카드가 아니라 **의식**입니다.

## 3. 카드 시스템

### 3.1 규격

포커 카드 비율(63 × 88 mm)을 따릅니다.

```
1x    630 × 882 px       코너 28px
2x   1260 × 1764 px      ← 실제 에셋 출력 배율
안전영역   내측 48px (1x 기준)
타일 그리드  6열 × 9행 = 54칸, 칸 크기 105 × 98 px (1x)
```

**타일 그리드가 630 × 882에서 정확히 나누어떨어지도록** 이 치수를 고정했습니다. 바꾸지 마세요.

### 3.2 카드 뒷면 — 1종

전 카드 공용입니다. 조커가 사라지면서 변형 뒷면도 필요 없어졌습니다.

**다만 야바위에서 이 한 장이 매우 중요해집니다.** 세 장이 빠르게 자리를 바꾸는 동안
플레이어는 뒷면만 보고 자기 카드를 추적합니다. 그래서 뒷면은

- **회전 대칭이면 안 됩니다.** 위아래가 구분돼야 카드가 뒤집혔는지 보입니다
- **중앙에 시선을 잡는 앵커가 있어야 합니다.** 눈이 따라갈 지점이 필요합니다
- 세 장이 겹칠 때 경계가 보이도록 **테두리 대비를 충분히** 주세요

### 3.3 카드 앞면 — 6종

| ID | 슬롯 | 이름 |
|---|---|---|
| `gift-watch` | 선물 | 갤럭시 워치 9 |
| `gift-tab` | 선물 | 갤럭시 탭 |
| `gift-ebook` | 선물 | 이북 |
| `hotel-a` | 호텔 | 더미 A — 확정 후 교체 |
| `hotel-b` | 호텔 | 더미 B |
| `hotel-c` | 호텔 | 더미 C |

**앞면은 6종입니다.** 슬롯당 정확히 3장 — 3장이어야 야바위가 성립합니다.
조커는 없앴습니다.

**앞면 레이아웃 규칙**

```
┌─────────────────────┐
│  brass 얇은 이너 프레임  │  ← 내측 48px
│                     │
│    [ 이미지 영역 ]      │  ← 카드의 60%. 풀블리드 아님
│                     │
│   슬롯 라벨 (C2/brass)  │
│   카드 이름 (D3/ink)    │
│   한 줄 설명 (B2/soft)  │
└─────────────────────┘
```

이미지는 **풀블리드로 깔지 마세요.** 타일 그리드가 이미지 위에 얹히는데,
풀블리드면 타일이 벗겨질 때 카드의 테두리 정보까지 같이 드러나 힌트가 새어 나갑니다.

### 3.4 타일 우선순위 맵 — 카드마다 필요

각 앞면마다 54칸의 해제 순서와 잠금 좌표를 지정해야 합니다.
**디자인 산출물에 이게 포함됩니다.** Figma에서 카드 위에 6×9 그리드를 얹고,
각 칸에 번호와 상태를 표기한 오버레이 프레임을 카드별로 하나씩 만들어 주세요.

```
잠금 (14칸)   로고 · 제품 형태 · 간판 등 정답이 확정되는 영역
순서 1군      배경 · 여백  → 가장 먼저 열림
순서 2군      질감 · 주변 사물
순서 3군      피사체 외곽선 → 가장 늦게 열림
```

### 3.5 카드 상태 — 5종

각 카드는 다음 상태로 렌더됩니다. 상태별 프레임을 컴포넌트 variant로 만들어 주세요.

| 상태 | 설명 |
|---|---|
| `back` | 뒷면 |
| `void` | **탈락 카드.** `✕` + `탈락`. 내용을 절대 드러내지 않음 |
| `sealed` | 뒷면 + 밀랍 봉인 오버레이. 밀랍 색은 D-day까지 남은 일수에 따라 변함 |
| `revealing` | 타일 + 블러 + 채도 필터가 걸린 앞면. 진행도 0~100% |
| `open` | 완전히 드러난 앞면 |
| `codex-locked` | 도감용. 회색 실루엣 + `???` |

`revealing` 상태는 진행도 3단계(30% / 55% / 74%)를 대표 프레임으로 만들어 주세요.
개발자가 보간할 기준점이 됩니다.

### 3.6 밀랍 봉인 오버레이

카드 하단 중앙에서 45% 지점에 위치. 지름 220px (1x).
불규칙한 가장자리를 가진 원형 밀랍 덩어리 위에 **`0919` 각인**.

- 각인은 IBM Plex Mono, 밀랍보다 어두운 톤으로 눌린 느낌
- 가장자리는 좌우 비대칭. 완벽한 원이면 스티커처럼 보입니다
- `sealed` 상태에서만 표시

**깨진 상태**도 필요합니다 (`wax-broken`). 세 조각 이상으로 갈라진 형태를
개별 패스로 분리해 주세요. 개발자가 각 조각을 따로 날립니다.

### 4.4 빛기둥 — 상세

개봉 연출의 절정입니다. 2프레임으로 만들어 주세요.

```
프레임 A — 은색 (1.2초 유지)
  화면 중앙에서 위로 솟는 빛기둥. tell-silver.
  폭 240px, 화면 상단까지 관통. 가장자리 흐림 40px.

프레임 B — 금색 (폭발)
```

A에서 B로 넘어가는 0.2초가 이 앱 전체에서 가장 중요한 순간입니다.
**A는 의도적으로 초라해야 합니다.** A가 이미 화려하면 B의 폭발이 안 살아납니다.

## 5. 모션 스펙

Figma에서 프로토타입으로 만들 필요는 없습니다. **타임라인 문서로 넘겨 주세요.**

| 연출 | 길이 | 이징 |
|---|---|---|
| 야바위 셔플 (슬롯1) | 2.6s | 스왑 7회. 350→150→420ms **가속 후 감속** |
| 야바위 셔플 (슬롯2) | 1.8s | 스왑 5회 |
| 탈락 카드 뒤집기 | 1.4s | 느리게. 무게를 줌 |
| 페인트 (멈칫) | 0.9s | 20%에서 정지 + 화면 흔들림 ±4px |
| 카드 뒤집기 | 0.6s | `cubic-bezier(.2,.8,.2,1)` |
| 봉인 홀드 | 1.5s | linear (진행도가 정직해야 함) |
| 타일 1장 소멸 | 0.4s | `ease-out`, 장당 60ms 스태거 |
| 빛기둥 A | 1.2s | 정지 유지 |
| 빛기둥 A→B | 0.2s | `ease-in` |
| 밀랍 파괴 | 0.8s | 조각별 물리 낙하 |
| 화면 전환 | 0.5s | crossfade |

`prefers-reduced-motion` 대응은 개발 단계에서 처리합니다. 디자인에서는 고려하지 마세요.

## 7. 봉인 증서 (인쇄물)

> **HTML/CSS로 만듭니다.** PDF 라이브러리가 아니라 Electron의 `printToPDF`로 출력하기로
> 확정됐습니다 ([`tech-spec.md`](tech-spec.md) §0). 이미지 시안이 아니라 **웹 시안**으로 넘겨 주세요.

```
규격    A5 (148 × 210 mm) — @page { size: A5 }
색      paper 배경 + ink 텍스트 + wax 도장 1점
서체    Display (제목) + Mono (데이터)
여백    상하 30mm, 좌우 25mm
```

가정용 프린터 출력을 전제합니다. **넓은 면적의 진한 색을 쓰지 마세요.**
잉크가 번지고 종이가 우글거립니다. 선과 텍스트 위주로 구성하세요.

내용은 [`mechanics.md`](mechanics.md) §4.1 참고.

## 8. 작업 순서 제안

```
1주차   토큰 · 타이포 · 컴포넌트 라이브러리 (A)
        카드 뒷면 1종 + 앞면 6종 (B)
2주차   S02~S09 야바위 뽑기 흐름 (C) ← 화면 수가 가장 많습니다
        대기 메인 3변형 (C) ← 가장 오래 걸립니다
3주차   S10 · S11 데일리 키, S14 · S15 · S16 개봉 (C)
        모션 타임라인 (D)
4주차   나머지 화면, 썸네일 (E), 증서 (F)
        타일 우선순위 맵 6장 (B, §3.4)
```

**타일 우선순위 맵을 마지막까지 미루지 마세요.** 카드 앞면이 확정되어야 만들 수 있지만,
이게 없으면 개발이 대기 화면을 완성할 수 없습니다. 앞면이 나오는 즉시 착수해야 합니다.

## 9. 제약과 확인 사항

- **폰트 라이선스** — Pretendard(OFL) · Gowun Batang(OFL) · IBM Plex(OFL) 전부 임베드 가능
- **제품 이미지** — 갤럭시 제품 공식 이미지 사용. 카드 앞면에서 잘리지 않게 여백 확보
- **호텔 사진** — 실제 예약한 객실 타입의 사진이어야 함 ([`hotels.md`](hotels.md) §4)
- **다크 전용** — 라이트 모드 없음. 앱은 항상 어둡습니다
- **에셋 포맷** — 이미지 WebP, 벡터 SVG, 아이콘 `.ico`. 전부 앱에 번들되므로 총 용량 50MB 이하
